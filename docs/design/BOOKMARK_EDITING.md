# しおり編集

M4の実装前に固定する範囲。既存SPEC・ACCEPTANCEの保持条件は変更しない。

左の「しおり」から編集を開く。既存の階層を一覧にし、追加、名前変更、移動先ページの変更、上下移動、階層を深く／浅くする、削除を行う。削除は選択項目とその子を対象とし、実行前にその範囲を表示する。編集ダイアログ内では候補の一覧だけを変更し、「文書へ適用」で1回のUndo操作として反映する。キャンセルで本文・未保存変更・しおりを変えない。

新しいしおりの宛先は現在ページを全体表示する通常PDFの明示宛先（Fit）。既存のXYZ／Fit系・名前付き宛先、表示倍率・位置、色・太字等、未知の追加属性・非対応アクションは、名前や階層だけを変える場合にそのまま保持する。宛先を利用者が明示変更したときだけFit宛先へ置き換え、旧アクションとの両立しないキーを除く。外部URLや実行アクションを新規作成せず、編集により既存アクションを実行しない。階層の展開状態を保存する。

PDF標準のOutlines、Title、Parent、First／Last、Prev／Next、Countを使う。設定の別ファイルや独自形式を要求しない。タイトルは単行1〜200文字、最大1000項目・32階層。入力の重複参照、循環、破損した兄弟／親子関係やこの上限を超えた既存一覧は、部分編集で残りを消さず編集を拒否する。原本・本文・ページ辞書・既存注釈・フォーム・OCR文字情報は保持する。

反映処理は元のスナップショットから候補PDFを作り、成功時だけ一度commitする。日本語名、階層・順序・展開状態・宛先保持、宛先の変更、全削除、保存後の再編集、取消と不正入力を実行する。独立したPDFパーサーでポインターとCount、Unicode名と宛先、本文保持を検査し、本アプリの閲覧側で保存後のしおりを使って実際に移動する。既存回帰を省かない。Qt offscreen操作をネイティブIME・Reader GUI試験と呼ばない。
