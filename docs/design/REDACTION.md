# 真の墨消し：設計と技術評価

M5の拡張機能。SPEC・TECH・ACCEPTANCEの初版条件を変更しない。実装前の基準として、範囲内の文字・OCR文字・画像画素・注釈／フォームの値と外観を出力から除去し、範囲外の検索可能な本文、編集可能なフォーム・注釈、ページ座標を保持する。矩形を重ねただけの結果を墨消しと呼ばない。

操作は範囲の指定と確認、別の新規PDFへの適用を分ける。指定中は移動・取消が可能。適用済みコピーには削除対象の履歴を含めない。原本・現在の未保存状態・Undoを保持し、失敗や取消で出力を確定しない。既存の保護・証明書署名制限を無警告で解除しない。通常保存を画像化する方式で代替しない。

出力の監査は表示や検索だけに限定しない。独立したPDFエンジンで抽出した文字、フォームのV/DV/AP、全オブジェクトと展開ストリーム、画像の元画素、メタデータ、添付、到達不能オブジェクト、過去リビジョンを確認する。共有画像、Form XObject、隠れたレイヤー、クリッピング、ActualText、回転とUserUnitは対象に含め、安全に扱えない構造は理由を示して処理を拒否する。未評価の文書全般について復元不能を保証しない。

まず固定PDF4QTの `PDFRedact` と内容編集APIを、専用の `PDFTatsujinRedactionProbe` で比較する。これはEXCLUDE_FROM_ALLの診断用実行ファイルで、製品メニュー・配布物には入れない。診断出力は機密情報を残し得るため実務文書には使用しない。`prepare-redaction-probe.py` が公開可能な合成文書と実行前の判定条件を作成する。実行成功と採用可能性を区別する。

PDFRedactは全ページを描き直す。静的調査でフォーム・注釈・UserUnitの保持不足、本文のアウトライン化、画像の塗り方の疑義を確認した。編集APIの単純な要素削除も、元のリソースや不可視文字を残す可能性がある。この段階では両方式を安全な製品機能として採用していない。

実ファイルの比較でもPDFRedactの画像内部の残存画素、範囲外本文の検索不可、フォームとUserUnitの欠落を確認した。内容編集APIは標準Helveticaの書き戻しでエラーになる例を確認した。代わりに、元の文字コードを変えずに命令を保持し、対象文字命令を進み量へ置換し、画像は対象画素を除去した新しい可逆圧縮画像へ差し替える内部処理を追加した。ページ座標と範囲外のフォーム・署名を保持し、対象のフォームグループ、関連注釈、Info／XMP、添付、サムネイル、到達不能オブジェクトを整理する。候補は別のメモリ状態に作り、元文書へ反映しない。

現段階は限定した実験用候補生成であり、製品UIにはまだ公開していない。文字命令の一部指定、注釈や同一フォームグループの一部指定、描画パス、Form XObject、インライン画像、画像マスク、レイヤー、構造タグ、縦書き、スクリプト、証明書署名・暗号化文書等は拒否する。未対応を安全に処理した結果とは呼ばない。共有リソース・複雑なクリッピング・多様な日本語OCR・未知属性の機密情報・外部互換性と、利用者向けの確認／保存経路は引き続き実装・評価が必要である。

SDKの命令処理後フックはnoexceptのスコープ終了処理から呼ばれるため、そこでエラーを投げない。エラーは次の通常フックまたは候補終了時に通知する。不正な部分指定と処理中取消を含む異常系を実行して確認する。

削除する文字の進み量には表示用のFreeTypeの丸め値を使わず、PDFのWidths／W／DWと文字間隔を使う。幅を省略できる標準14書体は、ReportLab 4.4.9の固定した幅データから生成する。BSD条件と著作権表示は `licenses/REPORTLAB_METRICS_LICENSE.txt` に保持し、入力各ファイルと生成ヘッダーを `scripts/standard-font-metrics-source.json` で固定する。フォント本体は含めず、実行時のPython依存は追加しない。同じテキストオブジェクト内の後続17文字についてPDFiumの保存前後の座標が一致することを検査する。削除対象の個々の文字幅列は残さず、合計の進み量だけを出力する。

操作上の比較資料：[Adobeの墨消し手順](https://helpx.adobe.com/acrobat/desktop/protect-documents/redact-pdfs/redact.html)。範囲指定・適用・保存の分離と隠れた情報の扱いを参考とし、互換や安全性を比較済みと主張しない。

フォントの未使用ToUnicode／CID情報や埋め込みサブセットから削除対象を推測できないこと、任意の添付・未知属性・共有リソースの保持経路も今後の評価対象とする。現在の固定合成文書の成功だけを文書全般の安全性の証明とはしない。
