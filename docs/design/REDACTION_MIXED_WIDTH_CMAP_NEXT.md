# 次の限定墨消し範囲：埋め込み1/2バイト混在CMap

## 次の機能群と範囲

現在の`src/redaction_cmap.cpp`は、埋め込み・横書き・固定2バイトのEncoding/ToUnicode CMap、BMPの単一Unicode対応だけを受け入れる。次のまとまりは、同じ文書の埋め込み横書きCMapにある1バイトと2バイトの文字コードを、正確に区別して対象文字を除去し、残る文字と座標を保存すること。コード長と値を一体で扱い、Encodingの（コード長,値）→CID→GIDと、ToUnicodeの（コード長,値）→Unicodeを別経路として資源bindingごとに保持・照合する。GIDからUnicodeを導出しない。

最初は1コード→BMPの1文字を維持する。多文字Unicode、サロゲートペア、縦書きWMode、UseCMapの継承・外部資源、3/4バイト、未知命令はこのまとまりの受入根拠にしない。保持の意味が未評価の構造を、黙って2バイトへ切断したり無ヒント化したりしない。後続段階では多文字と継承を別の入力・設計・正解で扱う。

## 文字間隔Tw/Tcの最初の境界

`src/redaction_content.cpp`は、Twが1バイトのコード32に作用しIdentity-Hの2バイトコードには作用しない違いを記録している。現在はType0のwordSpacingを0とし、独自CMapのUnicode空白と非0 Twの併用を拒否する。混在入力の1バイトコード32をIdentity-Hへ再符号化すると、この前提のままでは元の単語間隔が失われ得る。コード32への作用をUnicodeの空白だけから推定しない。

最初の混在CMap単位は、対象の文字演算子が使う有効Tw=0へ範囲を限定する案とする。未評価の非0 Twを、原本・未保存状態・Undoを保持して非反映拒否する。二重引用符命令が設定するTwも同じ条件で検査し、値を0へ書き換えて成功扱いにしない。Tcはコード長ではなく描画文字ごとの移動として、除去分と保持分へ正しく一度だけ反映する。非0 Tcの保持も固定位置正解と実試験なしで合格にしない。

非0 Twを受け入れる前に、1バイト32→空白、1バイト32→非空白Unicode、空白Unicode→32以外/2バイト、正負Tc/Tw、Tj・TJの正負数値調整・単引用符・二重引用符を分離した入力を先に固定する。文字サイズ・水平倍率・Tm/T*と各演算子の有効Tw/Tc、各コードの幅、保持/除去後の全原点を製品serializerと独立に計算し、後続文字の位置と両エンジン描画を既存閾値で照合する。再符号化に必要な間隔補償の成否を、文字抽出一致だけで代用しない。

## 実装前の固定入力

利用条件とSHAを確認した既存合成PDFから、新しい保存先へ別の入力群を作る。実装前にPDF bytes、各資源bindingのEncoding/ToUnicode bytes、codespace範囲、実際の文字列bytesとコード分解、CID/GID、Unicode、幅、原点、輪郭・使用回数・複合閉包を固定する。生成済み入力を別担当が独立に解析し、出力から正解を作らない。

成功候補は、1バイトのみ、既存2バイトのみ、曖昧さのない混在、各長さの下限/上限、複数codespace、cidchar/cidrangeとbfchar/bfrange配列、同一CIDへの意味が一致した別コードを分ける。混在は、1バイトの先頭範囲と2バイトの先頭範囲が重ならない条件をまず固定する。Tj/TJ/引用符命令、同じ字体の別名、別ページ・兄弟Form・注釈N/R/D外観を別条件で追加する。既存字体・ヒントの受入条件は変えない。

拒否候補は、長さをまたぐprefix曖昧性、同じ長さの重複codespace、範囲外コード、切断された2バイト、同じコードの再定義、Encodingだけ/ToUnicodeだけにあるコード、CIDとUnicodeの不一致、値の桁溢れ、UseCMap辞書/命令、未知構造。表内の値が偶然同じ場合も、コード長を無視して結合しない。0のコード値とCID0/Unicode NULの意味を区別し、現在の拒否条件を変える場合は別の差分として先に固定する。

拒否は実Qtの完了記録、原本/未保存状態/Undoの保持、出力不在を揃えて判定する。実行記録のない出力不在は拒否PASSにしない。

## 構造と独立検査

入力のコード区切りは製品decoderを使わず、固定codespaceと生bytesから復元する。各資源bindingでEncodingの（コード長,値）→CID→GIDとToUnicodeの（コード長,値）→Unicodeの両経路・意味・使用数を独立に検査し、PDFium/pypdfの文字抽出と位置を別に確認する。除去対象の文字列に同じUnicodeが別の保持場所でも使われる条件を用意し、正当に保持する単字と、除去すべき文字列・対応表・旧字体を混同しない。

保存後の全FontFile2/GID閉包、輪郭・flags・metrics・他命令・checksumを確認する。ToUnicode/Encodingの旧ストリーム、未到達の資源、展開ストリーム、PDF生bytesも検査し、古い文字対応や字体を孤立物として残さない。共有先ごとの局所字体と、同一元SFNT SHAの最終到達参照unionを分ける。CID対応だけが一致する別元payloadを共有の根拠にしない。

位置誤差は既存0.5pt以内。PDFiumとPopplerを別集計し、72/96/300dpiの既存1px矩形境界外差0、対象外ページの全画素一致を維持する。未知構造の拒否、取消、未保存署名、Undo/Redo、保存後再編集は同じ実Qt入口で確認する。
