# 縦書き文字の原点と外部ハイライト

dev17の保存文書はFirefoxで検索・連続コピーが成功するが、検索ハイライトは固定2mmに対して2.319〜3.028mmで未達。正解・検索語・閾値を維持する。不可視文字の描画位置と文字選択のセル原点を混同せず、標準PDFの縦書き位置ベクトルを使って分ける。

根拠はAdobeが公開する[ISO 32000-1の9.7.4.3／Table 117](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf)。W2の3値は送りと原点のX・Y。省略時はDW2のYと水平幅の半分を使う。字体は同じ埋込みプログラム・Unicode・個別の送りを共有し、原点だけをPDFの字体メトリクスへ保存する。画像・注釈・署名を固定化しない。

PDF4QTの固定版に対する既存のフォント派生処理を拡張する。上流checkoutと公開ヘッダーABIを変更せず、内部のType0派生字体に標準の原点を持たせる。実字形は原点分だけ移動し、文字配置を上端へ移しても描画と本アプリの検索枠が元の位置を保つ。字形キャッシュはCID出現ごとに複製せず、GIDと原点の組で共有する。水平字体は従来処理を保ち、不正なW2座標は拒否する。

文字層は各字形を標準のSpanで区切り、外部ビューアが列全体の均一なセルへ再配置することによる位置差を避ける。[Mozillaの文字抽出](https://raw.githubusercontent.com/mozilla/pdf.js/master/src/core/evaluator.js)と[文字層](https://raw.githubusercontent.com/mozilla/pdf.js/master/web/text_layer_builder.js)の挙動を参照した。コードは取り込まない。このSpanだけで構造化タグや読み上げアクセシビリティの合格を主張しない。

先行した私的コピーでは、Readerの平坦化ページへ置いた新Contentsがwriterのページへ保存されない診断不備があった。実保存ストリームを照合するコピー生成へ修正し、PDFiumの最大字形差0.011pt・可視画素差0を確認した。原点だけではFirefoxの列セル高さが未達。各字形のSpanも含むコピーで、PDFium／pypdfとFirefoxの3検索語・連続コピー・位置約1.4mmが成功した。これは製品出力ではなく、元のFAILと診断不備を保持する。

製品実装後に、元D11から実OCR、保存・再編集・Undo・取消・検索・選択コピーを実行する。W2単独／範囲／既定と同じGIDの異なる原点、水平保持を検査し、PDFium・Poppler・Firefoxでも保存2出力を照合する。全回帰・配布・通信能力ゼロを新バイナリへ結び付ける。回転・特殊単位・R01の未達をこの範囲の成功へ置き換えない。
