# フォームの作成・配置・再設計（M5）

継続指示に沿う次の拡張。既存SPEC・TECH・ACCEPTANCE・正解・閾値を維持する。初版のフォーム入力・XFDF入出力とは分け、標準AcroFormの6種類を本アプリで新しく作り、保存後に設計を変更できるようにする。既存の本文・画像・署名・注釈・フォーム・OCR・関連情報を保持する。

## 操作と対応範囲

「作成→フォームを設計」で、選択ページの実PDF、項目一覧、種類・内部名・表示ラベル・初期値・選択肢・位置・大きさを確認する。ページに範囲を描いて追加し、一覧・図面・mmの入力で選択・移動・サイズ変更・削除する。名前と表示ラベルを分け、保存前に重複と意味のある値を検査する。現在の日本語入力を確定した不変の候補を所有ワーカーで作り、明示適用時だけ1回のUndoで反映する。取消・失敗・文書revision変更では元文書と未保存状態を保持する。

新規作成は単行テキスト、複数行テキスト、チェックボックス、ラジオボタン群、コンボボックス、リスト。ラジオ群の共有フィールドと独立widget、選択値／表示ラベル、複数選択、最大文字数、読取専用・必須を扱う。単行へ改行を入れる、無効な初期値、重複する内部名・選択値、表示範囲外の矩形は拒否する。空の初期値でも利用できる外観を作る。必要なフォントと外観を文書へ埋め、再読込・入力・印刷でも正しく表示する。

最初の作成は平坦な内部名とし、階層区切りの`.`、NUL・制御文字・不正UTF-16は拒否する。既存の階層フォームは保持し、通常の入力とXFDFでは引き続き完全修飾名で扱う。本アプリで作った設計項目は専用の再編集メタデータと安定したIDで管理する。既存の他社フォームと非対応の項目は一覧へ区別して表示し、この第一段階でその設計を勝手に書き換えない。新しい項目で既存の名前を衝突させない。

回転・CropBox・UserUnitを含む表示上の実寸をPDF座標へ戻す。新しい欄は作成時の表示で読める方向に配置し、その後のページ操作へ追従する。通常保存を画像化で代替しない。計算・検証・送信・JavaScript、XFA、証明書署名フィールドの設計は対象外。暗号化・証明書署名・非対応文書の保護を解除しない。項目削除を機密情報の墨消しとして案内しない。

## フォントと成立性を先に確認する

入力値の外観だけでなく、他ビューアが編集に使うAcroFormの既定フォントも検証する。現在の同梱Notoから、固定した生成手順で通常ウェイトのTrueTypeとUnicode対応表を用意する案を先に検証する。WindowsのMeiryoファイルを配布へ取り込まない。OFLの著作権・予約名・改変表示を維持し、元のフォントと生成物をSHAで照合する。追加の生成依存はビルド／開発時に限り、配布アプリへPython等を要求しない。

初期値に現れない日本語・異体字・補助平面の文字を、保存後に外部ビューアで入力できるか確認する。CID・GID・ToUnicodeを混同せず、別のUnicodeが同じ字形を持つ場合も入力と抽出を変えない。不足がある方式を完成扱いせず、既定フォントの技術検証結果を残して修正する。文書内のフォントは共有し、項目ごとに同じ完全フォントを埋めない。

実装は固定元フォントのウェイト400から生成するTatsujin Sans JP Regularを採用する。Type0 / Identity-H、UnicodeごとのCID、CIDToGIDMap、UTF-16BEのToUnicodeを保存し、AcroFormの既定リソースと各項目の外観で完全フォントを共有する。空欄からの外部入力でも初期値だけのサブセットに依存しない。生成レシピ・fontTools版・元と成果物のSHAは依存lockで固定する。通常のリンク配置も使うページ範囲プレビューを共通化し、フォーム設計のプレビュー・適用は取消できる所有ワーカーで行う。

開発環境では資産の初回取得前に `python -m pip install --target tools/python fonttools==4.60.1` を実行し、`PYTHONPATH` に `tools/python` を設定する。`python scripts/fetch-assets.py` が生成物の不足時にレシピを呼び、元・成果物を検証する。`--verify-only` は不足・改変時に失敗し、既存の異なるファイルを上書きしない。単独生成は `python scripts/derive-form-font.py`。

既存PDF4QTの本文抽出APIは補助平面文字を1個のQCharへ変換できない場合がある。この実装はフォーム値と専用外観のUnicode対応を保持し、通常の入力欄ではそのままコピーする。任意のPDF本文の補助平面文字検索・コピーまで修正済みとは扱わない。表示ラベルは項目の説明・ツールチップであり、紙面に静的な説明文字を追加する機能ではない。既存の他社フォームの設計変更は対象外。

## 実装前の試験条件

新規の設計項目は最大1000widget、内部名256文字、表示ラベル1024文字、値／選択肢は各65536文字・選択肢1000件、設計データ全体16MiBの上限を置く。各候補の項目参照・親子関係・ページ注釈配列・外観・値・PDF座標を検査し、壊れた構造・上限超過で部分反映しない。既存項目と未知の属性を保持する。

- 6種類の作成と日本語の値・ラベル・選択肢、ラジオの共有値と別widget、リスト複数選択・最大文字数。通常保存→本アプリ再編集と入力→Undo／Redo→再保存を実行する。
- 4回転・CropBox原点・UserUnitのページへ配置・移動・サイズ変更・ページ回転。保存座標は既存0.5ptの条件を維持し、独立エンジンで外観と位置を照合する。
- 既存フォーム／階層名／署名／注釈／リンク／しおり／XMP・Info／実日英OCRを保持。XFDF入力データと通常入力、保存後検索・コピーも実行する。
- 値を入れていない新規欄を外部Firefoxで開き、初期値に含まれない日本語を入力・保存し、別エンジンで文字と外観を読む。予約名・フォントライセンス・埋込み条件と再現性を検査する。Reader GUIは実行できない場合に未実行と明記する。
- 不正な名前・重複・選択値・参照・矩形・上限、初期／途中取消・worker失敗・revision更新で原本とUndoを保持。元の文書・通常保存先を設計ダイアログから直接上書きしない。
- 実ダイアログで配置・選択・移動・サイズ変更・一覧と設定の同期、コンパクト表示、取消・明示適用を実行する。全回帰・独立検査・通信権限なし・配布物の実展開を実行し、未実行のネイティブUI・外部環境を別に追跡する。
