# ビューアの要件・操作・実装設計

2026-10-04 / 設計版 1 / 対象：PDF達人の閲覧体験

**目標は「Acrobatから迷わず移れて、日常の閲覧ではさらに快適」です。** 文書を読む場所が安定し、手を動かした分だけ反応し、検索や参照から迷わず戻れることを製品の中心に置きます。機能の多さや装飾では評価しません。

本書はユーザーの「ビューアを最重要として要件定義・設計から行う」という依頼に対する補足設計です。[SPEC](../../SPEC.md)・[TECH](../../TECH.md)・[ACCEPTANCE](../../ACCEPTANCE.md)の正本、M1の正解・閾値・受入条件を変更しません。「提案」と記した初期値や新しい検証目標を、ユーザーが個別承認済みとは扱いません。M2の機能開発を開始する文書でもありません。

[操作できる画面案](viewer-prototype.html)は合成HTMLを使った設計プレビューです。実PDFの描画・検索・保存・OCRの実装証拠にはしません。設計後、連続表示・読書位置保持・非同期検索・表示履歴を製品へ組み込みました。[最新の検索と履歴の検証](../testing/M1_SEARCH.md)、[連続ビューアの検証](../testing/M1_VIEWER.md)を参照してください。以下の現状分析は改修前720c229を基準とした記録です。

後続で[本文選択の実装設計](TEXT_SELECTION.md)に基づき、ページをまたぐ選択・自動スクロール・非同期文字読み込みを統合しました。[実PDFでの試験結果](../testing/M1_SELECTION.md)はV06/V07の一部を扱います。OSクリップボード実操作、文字カーソル、縦書き・複雑な段組み等の未確認範囲を含め、設計全体の完成とはしていません。

## 1. 何をもって快適とするか

2026-10-05には[手のひら操作](HAND_TOOL.md)を具体化し、既存スクロールへ統合した。[実行結果](../testing/M1_HAND.md)はV07のSpace・署名との競合・取消を扱う。実OS入力やAcrobat比較は未実行で、設計全体の合格宣言ではない。

続いて[しおり・リンクの操作設計](DOCUMENT_NAVIGATION.md)を具体化し、階層・宛先・ページラベル・表示履歴へ統合した。[実行結果](../testing/M1_NAVIGATION.md)はV08の回転・名前付き宛先・無効参照・復帰を扱う。BBox形式や外部リンクを開く操作は残る。以下の改修前の現状分析とは区別する。

### 利用場面と優先順位

| 優先 | 利用場面 | 成功の定義 |
|---|---|---|
| 最優先 | 文書を開いて読む | 最初のページが読め、操作を覚えずホイールで次ページへ進める。設定画面を経由しない |
| 最優先 | 長い文書の途中を読む | ズーム、ウィンドウ変更、検索、署名、OCRを挟んでも元の箇所へ戻れる |
| 最優先 | 語句を探して前後を読む | ページ番号だけでなく一致箇所へ移動。前後の文章が見え、次の一致・元の場所へ迷わず移れる |
| 最優先 | 本文をコピーする | 選択範囲とコピー内容が一致する。複数行・ページ境界・日本語でも余分な文字を混ぜない |
| 高 | ページ・目次・文書内リンクをたどる | 物理ページ番号と文書内のページラベルを区別。履歴で元の表示へ戻れる |
| 高 | スキャンを読む・検索可能にする | 画像だけでもすぐ読める。必要時に同じ画面でOCRし、終了後も表示位置を保つ |
| 高 | 読みながら署名して保存する | 閲覧と編集の状態が明確。読むだけでは文書の未保存状態やUndo履歴が変わらない |

「読んでいる位置を失わない」「反応を待たせない」「検索・コピーが信用できる」の3点でAcrobatを上回ることを目指します。比較実測と利用者評価を通るまで「Acrobatより速い／使いやすい」と表示しません。

### 既存アプリとの差と、先に直す理由

| 現状（720c229） | 不便さ | 設計で解消すること |
|---|---|---|
| 1ページずつ表示し、refreshでsceneを再生成 | ページ境界で読む流れが切れる。更新時に位置を失いやすい | 連続レイアウトとPDF上の読書位置を保持する |
| 固定倍率1.5の画像をビューで拡縮 | 高倍率・高DPIで文字がぼやける | 実表示倍率とDPRに対応した描画へ差し替える |
| 同期の文書全体検索、ページ単位の結果 | 待ち時間と一致箇所への往復が分かりにくい | 非同期検索、一致ごとの結果、文書表示の履歴 |
| 矩形選択の見た目、単ページ中心 | 選択した文字とコピーされる範囲を予測しにくい | 文字列の範囲と字形ハイライトを対応させる |
| 表示・文字抽出ごとに描画コンテキスト作成 | 再計算とUI停止の余地がある | キャッシュ・優先度・破棄条件を明示し、計測する |

## 2. 要件の境界

| 区分 | 内容 |
|---|---|
| 既存仕様を継承 | 連続スクロール、ズーム、幅／全体表示、検索・コピー・印刷、中央PDF・左ページ・右設定、1ウィンドウ1文書、ローカル処理、読み取り専用、IME・キーボード、1024×720論理px以上 |
| 本設計の提案 | 連続・幅合わせを初期表示、表示履歴、しおりの閲覧、結果の抜粋、アンカーを保つ拡縮、集中表示、下記のショートカット・寸法・性能目標 |
| 今回の設計対象外 | タブ、分割比較、見開きの製品化、ホームの分析画面、テーマ追加、本文直接編集、注釈全種類、フォーム全種類の新規実装。既存内容の表示・保持は対象 |

全体表示と単ページ表示も選べる設計にします。初期表示の提案は実文書と利用者評価で確かめます。二段組み・縦書きのコピー品質は既知の限界を隠さず別評価し、横書き基準を緩めません。

## 3. 画面の骨格

```text
┌ 文書名・未保存表示                 開く  保存  印刷 ┐
├ 戻る 進む │ 選択／手のひら │ 検索 │ 署名 OCR     ┤
│ ページ/しおり/検索 │                             │
│                   │     PDF（連続した用紙）       │ 設定
│  サムネイル       │                             │ 必要時
│  または検索結果   │                             │ のみ
├ 状態・処理進捗    │ ページ / 総数 │ 倍率 幅 全体  ┤
└───────────────────────────────────────────────┘
```

- 文書が主役。中立色の作業面、白い用紙、選択とフォーカスだけに青を使います。影・アニメーションで操作状態を表現しません。
- 文書操作と閲覧操作の位置は固定します。右側は通常閉じ、署名・OCR・選択要素の設定時だけ開きます。未実装機能は製品の入口に残しません。
- **寸法の初期案**：上部60＋48px、下部44px、左展開240px（レール48pxを含む）、右300px、用紙間24px。主操作・説明のUI文字13〜14px以上、補助メタデータは12pxを基本とし、主操作のクリック領域36px以上。1024×720で主要操作が欠けないことを先に検証します。
- 幅1200px未満では左右を同時展開せず、右設定を開くと左はレールにします。右を閉じると直前の左状態を復元。設定を勝手に隠さず、用紙上のアンカーを保持します。ドラッグ中にはパネル構成を変えません。
- 「集中表示」は左右パネルと作業入口を一時的に畳み、ページ・倍率・戻る・解除の入口を残します。OSの全画面にはせず、ユーザーの他の作業を妨げません。初期案ではF8で切替、Escでも解除できます。
- ドキュメント名は省略しても全文に到達でき、読み取り専用・未保存・OCR処理中は文字で表示します。右パネルの展開や検索だけで未保存表示を点灯させません。
- 見えている画面中央に最も近いページを現在ページとします。境界の同距離は前ページを採用。サムネイル選択と下部表示は同じ値を使い、スクロール中に左右パネルを自動で切り替えません。

## 4. 操作の仕様

### 4.1 開く・読む・移動する

- 開く／単一ファイルのドロップで読み込みます。別文書を開く場合は既存仕様どおり別ウィンドウ。壊れたPDFをパスワードエラーにしません。読込失敗で既存の作業を消しません。
- ページの外形を先に確定し、表示ページを優先して描画します。描画未完了のページは「描画中」、失敗時はページ番号と再試行を表示。空白ページと混同しません。
- ホイールは連続スクロール。タッチパッドのpixelDeltaを尊重し、ページへ強制吸着させません。慣性はOS入力と二重適用しません。既定で長い補間アニメーションを追加しません。
- PageDown／PageUpは表示高の90%移動し、10%重なりを残します。ページ単位移動はCtrl+PageDown／Upと前後ページボタン。スクロールバーで文書内の位置と長さが分かります。
- ページ番号欄は物理ページ（先頭から1）を入力。範囲外・空欄・文字はその場で説明し、勝手に丸めず現在表示を変えません。PDFのPageLabelsがある場合は「本文 3（5 / 20ページ）」のように併記します。
- サムネイル・しおり・内部リンク・検索への明示的なジャンプは**表示履歴**に記録します。履歴の戻る／進むはページ、PDF上の位置、倍率と表示モードを復元します。戻った後の新しいジャンプは進む側を破棄。ホイールの1刻みごとに履歴を増やしません。
- 表示履歴と文書のUndoは別です。検索から「戻る」で署名が消えたり、Undoで検索前へ戻ったりしません。検索結果を初めて開く際には、検索開始前の表示まで戻れる記録を残します。
- 通常セッション内の表示履歴はウィンドウごとに保持。文書パス・検索語・閲覧履歴の永続保存は本設計では既定にしません。最近使った文書の一覧も追加しません。

### 4.2 拡大・縮小しても迷子にならない

- 倍率は25〜400%をまず検証。Ctrl+ホイールはポインター下のPDF点を固定、ボタン・数値・パネル開閉は表示中央のPDF点を固定します。数値100%は96論理dpi基準の表示倍率であり、物理的な実寸保証ではありません。
- 拡縮途中は直前の画像を短時間再利用し、停止後に正しい解像度へ差し替えます。用紙が一瞬消える、以前の別ページが出る、文字がずっとぼける状態は不合格です。
- 幅合わせ／全体表示はモードとして保持し、ウィンドウサイズ変更時に再計算。手動倍率にしたら解除します。表示モードと実際の倍率を両方示します。
- **混在サイズの決定**：文書内の倍率は共通。スクロールで別サイズのページに入っただけでは再フィットしません。幅合わせの基準は最後に明示的に移動／フィットしたページです。横長ページでは横スクロールを許し、そこで「幅」にするとそのページへ合わせます。突然全ページの大きさが変わることを避けます。
- ページ回転は既存M1の文書変更として「ページを回転」と明示し、Undo・保存に反映します。一時的な表示回転を同名で混在させません。将来追加する場合は別操作として定義します。

### 4.3 検索して、前後を読んで、戻る

- Ctrl+Fで左の検索を開き、入力欄へフォーカス。検索結果は一致ごとの抜粋＋ページ番号を表示し、現在の一致を本文・一覧の両方で強調します。既存の本文文字層とOCR文字層を対象とします。
- 入力確定後150msの待ちを初期案とし、IME未確定中は検索を開始しません。現在ページから優先して検索しつつ結果一覧は物理ページ順・ページ内の読み順。未検索がある間は「検索中 12/100ページ・8件」のように表示し、0件と未完了を区別します。
- 進行中に開いた一致はIDで保持し、新しい結果が前に追加されても勝手に別の一致へ移りません。「次へ」は判明済みの次の一致へ進み、未検索の先へ達したら検索中と示します。全文完了前に末尾から先頭へ循環させません。
- 結果を選ぶと一致の上に約1/3画面の文脈を残して表示します。横方向は、用紙が収まるなら全幅を見せ、収まらなければ一致を見せるための最小移動にとどめます。検索語を横中央へ動かすために行頭を切りません。F3／Shift+F3と入力欄のEnter／Shift+Enterで次／前。最終から先頭へ循環した場合は「先頭へ戻りました」と通知します。
- EscはIME変換取消を優先。その後は検索欄から本文へフォーカスを戻し、検索語・結果は残します。×「検索を消去」で語句・結果・本文の強調をまとめて消します。パネルを閉じても検索を再開できます。
- 大文字小文字を区別しない検索を初期案とします。全半角や句読点を勝手に無視しません。改行をまたぐ検索は同じ読み順の連続行内で行い、段組みをまたいだ偽一致を作りません。比較文字列から元の字形範囲への対応を保持します。
- 画像だけのページを含む場合は「文字情報のないページがあります。OCRで検索可能にできます」と非モーダルに案内します。検索0件を理由に自動OCRしません。縦書き・段組みの精度は別評価です。

### 4.4 選択・コピー・手のひら

- 通常は文字選択。ドラッグ中は実際に選んだ字形を強調し、段落全体を覆う大きい矩形だけで代用しません。PDFの権限を尊重し、コピー不可なら理由を表示します。
- 文字の始点・終点を論理位置として保持。複数行、複数ページへ続けて選べ、領域外へのドラッグで自動スクロール。1ページずつ同じ文字を二重コピーしません。Ctrl+Cと右クリック「コピー」は同じ内容です。
- 単語のダブルクリック選択はUnicodeの単語境界を用い、日本語の挙動を実測。3回クリックで行を選ぶ案を別評価します。矩形内の単純な左上順だけで読み順を保証しません。
- 手のひらを明示的に選べます。本文にフォーカスがあるときだけSpaceを押している間、一時的に手のひらにします。入力欄、IME、フォームでは文字入力が優先。ツール切替・Esc・フォーカス喪失でドラッグを確定せず解除します。
- 選択できる文字のないページでは枠だけの偽選択を作らず、OCRの案内を表示。OCR後のコピーは文字層の品質に依存することを結果画面で明示します。
- フォーム入力領域と本アプリの追加要素の枠は既存SPECの優先順位を継承。通常閲覧で署名の全枠を常時強調しません。選択中だけ編集枠を表示し、読み取り専用では編集を開始しません。

### 4.5 キーボードとアクセシビリティ

これは本アプリの割り当て案であり、Acrobatの全ショートカット互換を約束するものではありません。

| 操作 | 割り当て案・フォーカス条件 |
|---|---|
| 開く・保存・別名保存・印刷 | Ctrl+O / Ctrl+S / Ctrl+Shift+S / Ctrl+P。通常の文書コマンド |
| 検索・次・前 | Ctrl+F / F3 / Shift+F3。IME未確定時は確定を優先 |
| ページ番号へ | Ctrl+L（本アプリ内）。Enterで移動、Escで元の番号へ |
| 画面単位・ページ単位で移動 | PageDown/Up・Ctrl+PageDown/Up。本文にフォーカス時 |
| 先頭・末尾 | Ctrl+Home/End。本文にフォーカス時 |
| 表示履歴を戻る・進む | Alt+Left/Right。テキスト編集中は入力欄の操作を優先 |
| 拡大・縮小、全体・幅 | Ctrl+Plus/Minus、Ctrl+0、Ctrl+1。本文にフォーカス時 |
| 一時的な手のひら・集中表示 | Space押下中・F8。本文にフォーカス時 |
| 操作解除 | Esc。IME→配置／ドラッグ→選択解除→集中表示解除の順。1回で複数を消さない |
| 文書編集のUndo／Redo | Ctrl+Z / Ctrl+Shift+Z。入力欄の編集履歴を先に扱う |

Tabの順序は文書操作→閲覧ツール→左パネル→本文→右設定→下部。本文をキーボードで選択する場合は「文字カーソルで選択」を明示的に有効化し、矢印・Shift+矢印・Ctrl+Cを使える設計とします。実装・読み順の検証前に対応済みとは表示しません。

色だけで状態を示さず、日本語のアクセシブル名、押下／選択状態、見えるフォーカスを付けます。設計目標は通常文字4.5:1、フォーカス・重要な操作境界3:1以上。スクリーンリーダーへ検索件数を毎フレーム通知せず、確定・完了時に通知します。Narratorによる実使用は別途必要で、DOM属性や自動検査だけでアクセシビリティ合格にしません。

### 4.6 外部リンク・保護・異常時

- 内部リンクは宛先へ移動し履歴へ登録。外部リンクは自動で開かず、クリック時に宛先を確認できる画面を出してからOSへ渡す案とします。HTTP(S)以外や外部ファイル実行は別途対応判断し、文書JavaScriptは実行しません。
- パスワード付き文書は正当なパスワードで開き、読み取り専用と許可されたコピー・印刷を扱います。証明書署名の検出と有効性の保証は分けます。機能制限の解除や平文保存へ誘導しません。
- 検索や描画の失敗はページと理由を表示し、保存成功・全文検索完了と混同しません。他ページの閲覧を続けられる状態を保ちます。

## 5. 状態と同時操作

印刷は上部とCtrl+Pから同じ経路へ到達し、選んだ範囲・用紙・拡縮・向きを確認して実行する設計です。範囲は物理ページ番号と表示し、横長ページの切れをプレビューで確認できます。印刷用描画と画面用描画を区別して注釈のPrint／NoViewを尊重し、取消で文書状態を変えません。高倍率閲覧のキャッシュ画像をそのまま印刷品質の代用にせず、印刷結果・実プリンター試験は既存受入に従って別途評価します。

| 状態 | 閲覧・検索 | 文書変更・保存 | 位置／取消の扱い |
|---|---|---|---|
| 読込中 | 進捗表示、取消可能。既存ウィンドウは応答 | 新文書は未確定 | 失敗時は元の作業を維持 |
| 通常／未保存あり | 使用可能 | 既存SPECどおり | 閲覧はdirty・Undoに影響しない |
| 検索・描画中 | 継続可能 | 使用可能。ただし新revisionへ追従 | 古い結果を表示しない |
| 署名配置待ち／ドラッグ | スクロール可能。拡縮等でドラッグは取消 | 解放時だけ1操作確定 | パネル移動で座標を変えない。Esc取消 |
| OCR処理中 | 開始時スナップショットを閲覧・検索 | 同一文書の変更・Undo・保存を停止 | 取消は部分反映なし。表示は利用者の現在位置を維持 |
| OCR成功 | 新文字層で検索を更新 | 1回のUndo対象 | 古い検索選択を再評価。フォーカスを結果ダイアログへ奪わない |
| 読み取り専用 | 許可された閲覧・検索・コピー・印刷 | 編集／OCR／変更保存なし | 理由を常時確認できる |

## 6. 応答速度と資源の設計

### 測る体験と目標案

以下は基準計測と実機評価で採否を決める**追加目標案**です。SPECの未確定な性能上限やA01〜A12を置き換えません。未達の結果を残し、目標変更には理由と比較を記録します。

| 観点 | 最初の目標案 | 測定方法 |
|---|---|---|
| 操作応答 | 入力から最初の視覚応答までp95 ≤100ms | パネル、検索、ページ移動、倍率、取消のイベントからpaintまで。完了時間と分ける |
| 連続スクロール | 60Hz表示で60fpsを目指し、キャッシュ済み区間のフレーム間隔p95 ≤33.3ms。100ms超停止を個別記録 | D10を20秒ずつ5回。実フレーム間隔と主スレッド停止時間を取得。平均fpsだけで判定しない |
| 拡縮後の鮮明化 | 操作終了から正しいDPRの可視領域完成までp95 ≤500ms | D01/D02/D10で100→200%、150%OS倍率を含む。低解像度の仮表示を完了扱いしない |
| 最初の可読表示 | デジタルD10 ≤2秒、画像D10 ≤3秒を暫定目標 | プロセス開始から最初の可読ページまで。cold/warmを分け、個別値を残す |
| 検索 | 結果を待つ間も操作応答目標を維持 | 初回結果・全文完了を別計測。検索中のスクロール・取消・別クエリを併用 |
| 長時間利用 | 5往復スクロール後にキャッシュが上限へ収束し、閉じた文書の資源を解放 | プロセス群のprivate bytes/working set、CPU、描画／文字／サムネイル別の内訳 |

既存のD10起動計測は少数回の初期基準であり、p95や競合比較には使いません。新しい比較では同一PC・同一入力ハッシュ・倍率・ウィンドウ・OS表示倍率・電源設定・バックグラウンド負荷を記録します。coldは可能なら再起動後を5回、warmは20回。実行順を交互にし、中央値・p95・最大値・全生データを残します。OSキャッシュを消せなければcoldと呼びません。

### 重くしない仕組み

1. 表示領域と前後1画面を優先。全ページの高解像度画像を作ってから開く設計にしません。高速移動中は飛ばしたページの要求を取り消します。
2. 描画・文字解析・サムネイルの優先度を分け、文字検索やOCRのCPU使用で入力を塞がないようにします。OCRワーカーは既存の分離を維持します。
3. キャッシュはページ数でなくバイト数で管理。初期検証値は描画256MiB、サムネイル32MiB／ウィンドウ。PDF本体・文字解析・ワーカー分を含む総メモリは別計測し、この値を総メモリ上限と偽りません。複数ウィンドウの共有上限は計測して決めます。
4. 高倍率は可視領域のタイル描画を候補とし、巨大な1枚の画像確保を避けます。上流の描画方式が同じ効果を持つか先に確認します。ページサイズの異常値・確保失敗でも文書を破損させません。
5. ズーム時の仮画像と鮮明な画像を同時に保持する時間を制限。古いrevision・DPRのキャッシュを解放し、非表示ウィンドウの先読みを止めます。日本語フォントやOCRモデルを削って軽くする方法は採りません。

## 7. 実装の境界と基盤選定

`Document`のPDF・履歴・保存を権威的な状態として維持し、閲覧は変更APIを通さず扱います。文書全体の作り直しに広げず、まずCanvasと表示状態の境界を作ります。

| 責務（名称は案） | 保持するもの | 保持しないもの |
|---|---|---|
| ViewerState | ページID、PDF点、画面内の位置、倍率モード、左／右パネル、表示履歴 | PDFへの未確定変更、保存先 |
| Viewport adapter | 上流の表示API、入力優先順位、アンカー復元、可視ページ集合 | 文書のUndo／保存 |
| Render scheduler/cache | 描画要求・優先度・世代・バイト上限 | 署名の確定座標や文書の所有権 |
| Text/search session | 読み順と字形対応、クエリ世代、結果ID、現在の一致 | 原本文字の正規化・書換え |
| Document | PDF・revision・変更履歴・安全な保存 | スクロール・選択・検索履歴 |

アンカーは「安定したページID＋PDF座標の点＋ビューポート内の相対位置」。ズーム後に同じPDF点が同じ画面位置へ来るようスクロール量を計算します。先頭・末尾でスクロール限界に達する場合だけクランプし、例外を試験に記録します。回転・CropBox・UserUnit・DPRを一つの正規変換経路で扱い、A04の0.5pt条件は維持します。

描画キーは文書ID・revision・ページID・表示回転・CropBox/UserUnit・倍率・DPR・閲覧／印刷用途。古いジョブの完了時には世代を照合し、別ページやUndo前の画像を出しません。QPixmap操作はGUIスレッド、ワーカーはQImage等に限定。PDF4QTの共有フォント／CMS／文書の並列安全性を仮定せず、まず上流の非同期機構を利用可能か確認します。

### 上流を活かす判断

固定済みPDF4QTには実際に以下のAPIがあります（ローカルヘッダーを確認）。存在確認は当アプリとの統合成功とは別です。

- `PDFWidget`：スクロールバー、キャッシュ上限、描画エラー、入力インターフェイス。
- `PDFDrawWidgetProxy`：連続レイアウト、`zoom(..., widgetPosition)`、`goToDestination`、`goToPageAndEnsureVisible`、表示ページ取得、先読み、非同期ページ／文字コンパイラ。
- `PDFSelectTextTool`：文字選択の入口。

**第一案は、独自の画面枠＋上流表示部をアダプターで包むこと。** キャッシュ・連続配置・選択を丸ごと再発明せず、画面と操作は本アプリの設計に揃えます。現在の独自Canvasをそのまま肥大化させる案は第一案にしません。ただし上流ウィジェットも使えば自動的にUXが完成するとは判断しません。

採用前にD02の座標、アンカー、署名オーバーレイ、既存の印刷フラグ、文字選択、OCRのrevision切替、ビルド依存・容量を検証します。満たせない箇所だけ上流修正の提案または自前の限定部品と比較し、理由をADRへ記録します。上流全体の画面や不要な編集機能は取り込みません。自前描画へ切り替える場合は可視ページを索引で求め、全ページを毎フレーム走査しません。

### Acrobatとの比較で「上回った」を判定する

同じPCと同じ公開可能な文書で、①開いて50ページへ移動して戻る、②語句を検索して3件目を読み元の場所へ戻る、③200%で読み幅合わせへ戻る、④2ページにまたがる文章をコピー、の4課題を比較します。作業完了時間、操作数、位置を見失って戻り直した回数、誤コピー、待ち時間を記録します。

初回は両製品に慣れる練習を用意し、順番を交互にします。第三者3〜5名の探索的評価を提案しますが、ユーザー募集を本作業の前提にはしません。参加者がいなければ未評価のまま、実装・自動試験を進めます。小人数の結果を全利用者への優越性へ一般化しません。AcrobatをこのPCで実行していない現状では、競合比較は未実行です。

比較で狙う差は、4課題すべてで誤操作を増やさず、特に「検索して戻る」「倍率を変えて読み続ける」で操作の少なさ・位置復元・待ち時間の改善を示すことです。評価項目は実行前に固定し、勝った文書だけを後から選んで優越を表示しません。見た目だけの好みと、実際の作業の速さ・正確さを分けて報告します。

## 9. 着手順と判断の出口

1. **今回**：この要件、操作・状態設計、操作できる画面案、狭い画面とキーボードの検査を提出。画面案を実装済み製品と混同しない。
