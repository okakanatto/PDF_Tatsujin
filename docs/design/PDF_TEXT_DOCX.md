# PDF本文を編集可能なWord文書へ取り出す

実エンジンの読込みでは、明示した自動字間の無効化も失われた。値表記、既定スタイル、互換モードの対照試験も失敗したため、アプリのOffice変換ブリッジで、単純な本文段落の明示設定を一致するロード済み段落へ引き継ぐ。原文・正解・検索語は変更せず、設定が省略された文書に一律抑制を適用しない。このブリッジを通した実エンジンと、生成DOCXの独立読取り・編集を検査する。単独LibreOfficeの設定保持は未達、Word実GUIは未実行として分けて記録する。

M6のOffice出力の最初の実装範囲を、コピー可能なPDFの本文文字を確認・修正し、新しいDOCXへ取り出す操作とする。元PDF、未保存変更、Undo、保存先は保持する。PDFの文字がWordで編集できることを実際のOfficeエンジンで検査する。単にページ画像を貼り付けて「編集可能」と表示しない。

この範囲は本文の取り出しであり、元のページレイアウト・画像・表・注釈・フォーム入力の完全復元とは区別する。これらが自動復元できると表示しない。後続のレイアウト復元を含むOffice変換機能群全体の完了に数えない。既存SPEC・ACCEPTANCEは変更しない。

入口は「作成→PDFの本文をWordへ」。選択ページの本文をプレビューし、取り出した文字・改行・順序を確認・修正してから保存する。画像しかないスキャンは空文書として成功にせず、既存のOCR操作を案内する。コピー禁止は尊重し、表示できることを取り出しの許可と混同しない。取り出せないページと理由を表示する。

DOCXには編集可能な段落・改行と明示的なページ区切りを記録する。文字集合を削らず、XML制御文字・不正なサロゲートは理由を表示して保存を拒否する。任意の文字列を実行コードや外部参照へ変えない。本文の先頭ゼロや記号を保持する。通常の取り出しと保存はWord・LibreOffice・Python・通信を要求せず、既存QtのOOXML出力を利用する。

出力は新しい.docxのみ。完成候補を作った後に、上書きしない方法で確定する。取消、書込み失敗、出力競合では既存ファイルと元文書を保持する。プレビューや抽出は非同期とし、古い文書・ページの結果を新しい表示へ反映しない。

初回実装前に日英・XML記号・明示改行・先頭ゼロ・複数ページ・画像のみ・コピー禁止の入力と正解を固定する。独立したZIP/XML読取りとpython-docxで本文・ページ区切り・編集可能性を検査し、専用LibreOfficeで実際に読み込む。UIの修正・保存・取消と保存競合、原本と未保存状態の保持を実行する。Word実GUIと一般レイアウト復元が未実行である場合、そのまま記録する。
本文のdocument／body／paragraph／run／text構造は[MicrosoftのWordprocessingML文書構造](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)、ページ区切りは[Breakの仕様](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.break?view=openxml-3.0.1)を参照する。SDK本体は取り込まず、生成したOOXMLを独立した読取ツールと実エンジンで検査する。
生成した段落では日英・日本語と数字の境界に自動の間隔を加えない。実エンジンで検索語の途中に空きが生じた失敗を保持し、[autoSpaceDE](https://learn.microsoft.com/ja-jp/dotnet/api/documentformat.openxml.wordprocessing.autospacede?view=openxml-3.0.1)とautoSpaceDNを段落へ明示する。元の正解や検索語を変更せず検査する。署名も注釈として保持するため、この本文取り出しには含めず、原PDFに残す。
