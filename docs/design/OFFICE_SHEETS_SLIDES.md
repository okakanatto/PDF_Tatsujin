# Excel・PowerPointからPDFを作成する

DOCX経路と同じ専用ローカルエンジン、原本保持、非反映の取消、新しい未保存PDF、実プレビューをXLSXとPPTXへ広げる。旧XLS／PPT、マクロ有効形式、外部データ、OLE／ActiveX、任意のOffice配置の同等性はこの経路の合格に含めない。DOCXの固定入力・期待値・試験条件は保持する。

共通OPC検査へ整理し、拡張子だけで判定せず、ContentTypesと本文パートでDOCX・XLSX・PPTXを照合する。既存のZIP・XML上限とCRC、パス、DTD、マクロ、埋込み、外部取得の拒否を維持する。XLSXの外部ブック・データ接続とWEBSERVICE／DDE／RTD等の外部処理数式は変換前に拒否する。読み込みはNEVER_EXECUTE・NO_UPDATEとし、原本・既存PDF・未保存変更を保持する。

Calcは元の印刷範囲、用紙、向き、縮尺、印刷対象シートを利用する。Excelと同じページ割りを一般保証せず、固定した印刷条件のページ数と文字・画像を検査する。Impressはスライドを1ページとして検査し、ノート・動画・アニメーションの再生をPDFへ引き継ぐとは表示しない。PDFへの変換後、署名・Undo・保存・再編集と検索・コピーを共通の経路で検査する。

入力と期待値は初回変換前に固定する。A4・縮尺100%・印刷範囲のある日英の2シート、元画像とSUMの期待値、2枚のスライド・文字・画像・固定サイズを合成する。マクロ、埋込み、外部参照、外部数式の入力も先に固定する。PDF4QTとPDFium・pypdf・Popplerで、ページ・文字・元画素・寸法を確認する。結果に合わせて正解を変えない。

エンジンは既存のLibreOffice 26.8.1.1を共有し、新しい大きな依存を取得しない。DOCXで判明したAppContainerのUNO接続制約は解消済みと扱わない。一般配布の判断、ネイティブUIとクリーンWindows等は別に追跡する。

生成したOffice PDFだけに文字抽出の互換処理を適用する。pypdfが正のTJ字間調整を絶対値で空白と誤認した実例に対し、26〜10000の正の整数を25以下の整数列へ分ける。総移動量、文字コード、負の調整、フォント・画像・資源・構造参照を維持する。ページ内容とFormの間接ストリームに限定し、インライン画像・入れ子配列は変更しない。実例の修正前後でPDFiumの文字座標差0、PDFiumとPopplerの全画素一致を確認した。正解文字の変更や抽出結果の空白除去は行わない。任意のフォントの文字抽出を一般保証する処理ではない。
