# 標準Latin字体の墨消し

2026-10-12、dev33の追加。基本4属性から作り直す限定条件をHelvetica／Times／Courier各4書体の12種へ広げる。FontDescriptor・ToUnicode・Widths・FirstChar・LastCharなし、既定／StandardEncoding／WinAnsiEncodingだけを扱う。Symbol／ZapfDingbats、独自属性の意味解釈、埋込み／hint／CFFの一般化は行わない。旧入力・正解・閾値は維持する。

基本字体名とEncodingをそのまま名前値で保持し、私有属性をコピーしない。字体を新規作成する適格判定を、原点保持の適格判定でも共有する。単位文字行列・倍率100%・Tc／Tw=0・字形だけの条件で空白字形による原点保持を用いる。型／宣言／共有資源と最終監査の既存条件は維持する。部分字形に対する既存拒否は維持する。

最初のstandard-font-families-v1（86c1deda…）はPDFiumの文字枠だけから作った24範囲だった。dev32はHelvetica2を生成し他22を拒否した。元字形を読み取る診断（b45e01a2…）で、Courier8条件の範囲がアプリの元輪郭上端を完全には含まないことを確認した。入力は不正PDFではないが、全字形包含という新しい成功条件の前提を満たさない。旧入力・期待出力・拒否／未達記録は保持し、成功扱いにしない。

standard-font-families-v2は同じ原本PDFを使う別の全字形包含条件。PDFiumの元文字枠とQtの元輪郭を各1ptの同じ余白で包含する範囲を、字体対応の製品変更前に固定した。生成は固定された元座標記録7b7d6bb8…を入力にする。実装後の出力を見て範囲を調整していない。CER、保持語、位置0.5pt、範囲外描画差0、既存境界1画素は変更しない。v1の部分範囲対応と一般M5合格は引き続き未達として追跡する。

最初の拡張は本番24条件を通したが、独立検査で太字の先頭2条件に52／56画素差を検出した。元原点との差は1ULP（約0.000015pt）だった。TJを再解析したfloat乗除算で元カーソルへ正確に戻る近傍値を最大32段階で選び、文字列化の再解析も同じfloatになることを確認する。合う値がなければ非反映で拒否する。最初の精密化は全除去の旧基盤3試験を拒否したため、保持字形がない場合も既知の零インク空白1個で原点を固定し、合計移動だけを出力する。元の秘密コード／個別幅／個数は出力しない。旧exe・FAILを保持する。
