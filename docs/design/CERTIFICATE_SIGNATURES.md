# 証明書署名の検証

M5の拡張。見た目の名前・画像による署名とは別の入口に置く。まず保存済みPDFの証明書署名を、元のバイト列でローカル検証する。既存の読み取り専用と編集・OCR制限は維持する。検証は原本、未保存状態、Undoを変更しない。署名作成はこの実装とは別の工程であり、未実装とする。

画面は「証明書署名を確認」。一覧で、署名対象の改変検出、対象が現在のファイル全体か以前のリビジョンか、証明書の現在時点のチェーン確認を分ける。署名者の証明書の名前・発行者・有効期間・SHA-256指紋を選択してコピーできる。PDF内の名前や日付を証明書の情報や検証済みタイムスタンプと混同しない。単一の「安全／有効」表示を使わない。

対象はadbe.pkcs7.detached／ETSI.CAdES.detachedの分離CMS署名。1署名辞書に1署名者、最大16署名、ファイル256MiB、CMS1MiBまでを今回の明示的な対応範囲とする。暗号化PDF、タイムスタンプ専用、旧RSA/SHA-1形式、未知形式、循環／過大フォームは理由を示して未対応とする。署名辞書がフォームに結び付かない場合も「署名なし」と表示しない。SHA-256以上の既知のハッシュとRSA 2048bit以上／EC 256bit以上を検査し、弱い方式を確認済みと呼ばない。

ByteRangeは整数4個、先頭0、正の長さ、順序・境界・加算の安全性を先に検査する。唯一の除外範囲がContentsの16進文字列全体と一致することを確認する。署名後の追加バイトは署名対象外として明示する。CMSは元のバイト列の2範囲で暗号検証し、証明書信頼確認を暗号的な改変検出から分離する。

信頼元はWindowsに既にあるROOT証明書の読み取りのみ。埋め込み証明書を信頼元に昇格させず、OSのストアを更新しない。検証に通信、OCSP、CRL取得、AIA取得を使わない。失効状態、署名時点の有効性、LTV、DocMDPの許容変更、タイムスタンプと法的な本人性は未評価と画面に表示する。ローカルチェーン成功を総合的な有効性と呼ばない。拡張用途がある証明書は文書署名用途の評価が別途必要であることを表示する。

長い検証は別スレッドで行い、進行中の表示と中止を維持する。開始時と終了時に読み込んだバイト列のSHA-256を開いた時の値と照合し、更新されたファイルの結果を表示しない。未保存変更がある文書は保存・開き直しを案内する。閉じる操作は中止を要求し、処理終了後に閉じる。

実装前の試験条件：信頼した試験CAの正常署名、同じ署名の未信頼判定、自己署名、期限切れ・有効期間前、本文1バイト改変、署名後の追記、CMS改変、不正ByteRange（負値・オーバーフロー・重なり・余分な範囲・Contents不一致）、空の署名欄、未知形式、複数署名、取消・入力更新、原本と編集制限の保持、実画面経路とキーボード操作を確認する。試験のCAはプロセス内にだけ渡し、OSにインストールしない。鍵は合成文書生成時のメモリ内で作成し、秘密鍵を成果物に保存しない。

ETSI.CAdES.detachedもCMSの暗号的な一致を検査する範囲に限る。CAdESの追加属性・プロファイルの適合やLTVを評価した結果とは呼ばない。

参照：[OpenSSL CMS_verify](https://docs.openssl.org/3.6/man3/CMS_verify/)、[証明書チェーン検証](https://docs.openssl.org/3.6/man3/X509_STORE_CTX_new/)。暗号的な署名検証を無効にするフラグは使用しない。
