# PDFの表を編集可能なExcelへ取り出す

元PDFを変更せず、現在のページの表範囲と行・列の境界を指定し、復元したセルを確認・修正して新しいXLSXへ保存する。画像としてExcelへ貼る方式ではなく、各セルの日英文字を編集可能な文字列として記録する。初期の境界は等分で、プレビュー上の境界をドラッグして実際の表に合わせる。罫線の自動認識や任意の表の意味復元が成立したように表示しない。

左に実PDFと範囲・境界、右にセル一覧を同時表示する。ページ、行数、列数、範囲選択を操作し、取り出した内容と配置を確認する。PDF文字層のないスキャンはOCRを案内し、成功した空表として出力しない。既存のOCR文字層は他のPDF文字と同じ検査を受ける。複数ページの結合、結合セル、縦書き・斜めの文字、複雑な重なりや自動の数値型推定は別の未対応範囲とする。

全セルを文字列として出力し、先頭ゼロ・日本語・英語・改行を保持する。「=1+2」のような内容をExcelの数式へ変換しない。外部参照や実行コードを作らない。内部の空セルを保持し、行の先頭・末尾の配置用空白だけを除く。明示的に編集したセルを再抽出時に破棄する場合は、操作に対応する確認を表示する。

表の専用プレビューではページ辞書の回転を外し、CropBox・UserUnitを反映した共通座標で文字をセルへ割り当てる。向きの変更は抽出用の表示だけであり、原PDFは回転しないことを画面で説明する。描画命令自体に縦・斜めの文字がある場合は未対応とする。文字が範囲端やセル境界にまたがる場合は、境界の調整が必要なことを表示し、黙って文字を欠落させない。文字抽出と描画は非同期で行い、ページや範囲を変更した古い結果を反映しない。取消・抽出失敗は原PDFの未保存変更・Undoへ影響しない。

出力は新しいXLSXのみとし、既存ファイルを上書きしない。作業ファイルに完成させてから確定し、途中取消・保存失敗・出力競合では既存ファイルを保持する。Qtの既存ZIP機能でOOXMLを生成し、追加のOffice本体・Python・大型依存を通常利用に要求しない。

初回実装前に、日英の4行3列、先頭ゼロ、数式に見える文字列、改行、内部空セル、画像のみ、回転・CropBox・UserUnitの文書と期待セルを固定する。PDF4QTの抽出に加え、openpyxlで出力の全セル・文字列型・改行・空セル・数式不在・関係を検査し、LibreOfficeで読み込みPDFへ変換して文字の利用を確認する。実UIの範囲選択・境界移動・セル編集・取消と、保存失敗・競合・原PDFの状態保持を実行する。未実行をPASSとしない。
