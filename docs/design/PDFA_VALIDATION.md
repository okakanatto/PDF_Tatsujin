# PDF/A適合性を読み取り専用で検証する

M6のPDF/A・意味情報評価の最初の範囲を、現在のPDFを専用のローカル検証器へ渡し、指定プロファイルに対する適合・不適合・検査未完了を区別して表示する操作とする。文書内のPDF/A申告や、通常の保存・再読込み成功だけで適合と表示しない。PDF/A変換・自動修復、タグ付けやPDF/UA全体の完了とは分ける。元のSPEC／ACCEPTANCEの要件・正解・閾値は維持する。

「作成→PDF/Aを検証」でPDF/A-1bまたはPDF/A-2uを明示選択し、JavaとveraPDFエンジンの実行先を指定する。確認対象は現在のPDFの作業用スナップショットであり、未保存の署名や編集を含む。PDFの原本・未保存状態・Undoは変更しない。保護・証明書署名の既存制限を尊重し、検査のために無断解除や通常保存の上書きを行わない。

処理は非同期とし、利用者のほかのJavaやOfficeを使わない専用Job Objectで実行する。取消・時間切れ・エンジン不在・XML不正・部分出力は合格にせず検査未完了とする。PDF本文・署名を通信で送らない。検査器の不足は設定画面で明示し、通常の閲覧・編集は維持する。

未編集の保存済み文書は、ロード時のSHAに一致する実ファイルのバイトを検査する。検査のためにPDFを再保存するとヘッダー・圧縮・メタデータ等を変え、元の適合性と区別できなくなるためである。現在の状態に未保存変更がある場合は、既存のPDF保存処理で作った候補スナップショットを検査し、その候補SHAを明示する。原本の適合結果を変更後の候補へ流用しない。暗号化された入力は無断で復号して検査せず、その理由を表示する。

結果には検査器の版、指定したプロファイル、適合／不適合、失敗した規則数・検査数と理由を表示する。XMLのDTD・外部実体を拒否し、サイズと件数を制限する。自動修復やメタデータの書換えは呼び出さない。版・プロファイルと文書のスナップショットを結び付け、検査後に編集された別状態へ以前の適合を流用しない。詳細をコピーし、新しいJSONへ保存できる。既存の結果ファイルは上書きしない。

実装前に、veraPDF公開corpusの対象プロファイルの適合例・不適合例、PDF/Aを申告するだけの非適合例、暗号化PDFの拒否、エンジン不在・取消・不正レポートと、原本・未保存状態を保持する条件を固定する。corpusはCC BY 4.0として出典・固定コミット・SHAと帰属を保持する。検査器の実行に先立ち、公式配布物の版・全体SHA・ライセンス・展開後サイズを確認する。

veraPDFは[公式インストール手順](https://docs.verapdf.org/install/)と[CLIのプロファイル／XML結果仕様](https://docs.verapdf.org/cli/validation/)を参照する。ライブラリ・アプリは[上流のGPLv3+／MPLv2+の選択条件](https://github.com/veraPDF/veraPDF-apps)を維持し、アプリのMITとは区別する。通常アプリとは別のプロセスとして構成し、正式同梱配布の条件確認は別途追跡する。[公式corpus](https://github.com/veraPDF/veraPDF-corpus)の既存のpass／failを、実装結果に合わせて変更しない。

本設計は作業中の拡張範囲である。実行前にPDF/A適合済み・PDF/A変換済みと表示せず、現在のWord候補dev14の一般出荷合格や残り単位の減算にも流用しない。

## 検証器の指定と再現

「作成→PDF/Aを検証」を開き、ローカルJavaのjava.exeとveraPDF CLIのcli-1.30.3.jarを指定する。公式インストーラーからCLIを導入し、画面で実行先を選ぶ。アプリは取得・更新・アップロードを自動実行しない。開発用の版・実行ファイル／JARのSHAはpdfa-engine-lock.jsonに固定している。一般アプリの配布ZIPにJava／veraPDFは同梱しない。

保存済みで未変更のPDFは、ロード時のSHAと一致する元バイトを検証する。未保存変更がある場合は現在の文書候補の別SHAを表示する。ロード後の外部更新・検証後の文書変更では以前の判定を使えず、開き直し／再検証を案内する。暗号化PDFは暗黙復号せず拒否する。署名付き文書の読取検証は文書を変更しない。

Windows開発環境の再現は、TATSU_PDFA_JAVA・TATSU_PDFA_JARへ実行先を設定し、TATSU_TEST_FILTER=M6Aでscripts/run-tests.ps1 -Headlessを使う。実行対象と出力先は同スクリプトの引数で新しいフォルダへ指定する。scripts/evaluate-pdfa-validation.pyは、保存した結果JSONと固定入力を別途veraPDFへ渡し、PythonでXMLを読む独立照合である。既存のA01〜A12・B01〜B08・C01〜C07を置換しない。

実行対象は2プロファイルの固定5文書であり、全corpus・全PDF/A形式・変換／修復・タグ／読み上げの適合を実証する範囲ではない。ネイティブ画面・クリーンWindowsは未実行として追跡する。
Javaの一時ディレクトリをUnicode引数で、設定・一時環境変数をその子プロセスに限定して所有作業フォルダへ指定する。親プロセスの環境を変更しない。制限されたWindows環境で検証器の書込可否判定が失敗する記録を保持する。生出力はShift JISであり、日本語パス自体の破損という初期診断は訂正した。元の権限条件のまま再試験し、失敗を未判定として追跡する。
