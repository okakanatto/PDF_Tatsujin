# 複数PDFの反復処理（M5）

継続指示に沿う拡張。SPEC・TECH・ACCEPTANCE・既存の正解と閾値を維持する。「作成→複数PDFをまとめて処理」で、保存済み入力の一覧と順番、処理、出力先、出力名を確認して開始する。現在の文書の未保存状態は入力に含めず、ダイアログへ明示する。元の文書・入力ファイル・Undo・保存先を変更しない。

## 操作・対象・失敗の意味

第一段階は日英OCRと画質を変えない容量最適化を選べる。OCR言語は日英／日本語／英語、対象は各入力の全ページ。単一文書の既存OCR処理と同じモデル・認識・保持・取消方式を再利用し、オンライン処理や自動ダウンロードを追加しない。最適化は既存の完全一致の共有・未使用回収・上限付きFlate処理を使い、画質を下げない。

最大100入力、入力ごと500ページ・256MiBまでとし、一覧の重複・同じ出力名・不正な出力先・既存出力は開始前に拒否する。元の名前に `_ocr.pdf` または `_optimized.pdf` を付けた新しいファイルを、指定した同じ出力フォルダへ保存する。同じ親フォルダ名や大小文字の違いでも出力名が衝突する場合は黙って置換しない。通常アプリの日本語・長いパス対応を維持する。

入力は順番に一つだけ処理し、所有ワーカーとOCR子プロセスで動かす。各ファイルの処理状態とOCRページ進捗、出力、失敗理由を一覧へ反映する。保護されたPDF・証明書署名・非対応フォームは解除せず失敗として表示し、次の入力へ進める。パスワードを保存・推測・一括解除しない。変更不要の場合は「処理不要」と表示し、同一内容のコピーを作らない。

成功したPDFごとに専用候補へ書込み・再読込検査して、入力の読込前後と確定直前のハッシュを照合する。既存出力を上書きしない原子的確定を使う。失敗ではその入力の出力を確定しない。入力更新・出力競合・書込み拒否・OCR異常は個別の失敗として記録する。

取消は現在の処理を中止し、その未確定候補を破棄して残る入力を「未処理（中止）」にする。既に保存済みの出力は保持し、一覧で保存済み／失敗／処理不要／取消／未処理を区別する。全入力が成功したように表示せず、全体を原子的な一括処理とも呼ばない。確定後の遅い取消は保存済みとして扱う。OCRは既存と同じ入力ごと15分の制限とし、時限超過を失敗として次へ進める。処理中に閉じる操作は取消と所有ワーカーの終了を先に行う。

## 実装前の試験条件

- 複数PDFの最適化・通常文書の処理不要・日本語フォーム／署名／画像／注釈／4回転／CropBox／UserUnit／しおり／リンクを保存し、入力のバイト・原本状態を保持。独立PDFエンジンで画素差0と本文・入力値・関連情報を照合する。
- 複数の日本語・英語スキャンへ実OCRを実行し、既存署名・フォームを保持。固定の検索語・CER・可視内容の条件を維持して、PDF保存後の外部検索・抽出と本アプリでのコピー・再編集を実行する。
- 不正PDF／コピー不可・暗号化／証明書署名／XFA、100入力・500ページ・256MiBの境界、同じ出力名、既存出力、入力更新、個別の途中失敗、確定競合、NTFS拒否、OCR子プロセス異常を検査する。成功した出力と失敗した入力の関係を固定正解で検査する。
- 開始前の取消、実処理中の取消、1件確定後の取消を確認し、成功済みのファイルを消さず、現在と残りの未確定出力を作らない。専用候補・子プロセスを片付け、原本・Undoを保持する。
- 実ダイアログで入力順・削除・処理・出力一覧・開始・途中取消・失敗後の再試行・完了後の再実行、800×480を実行する。処理中は一覧の編集を停止し、取消と進捗を維持する。
- 全回帰、独立検査、通信権限なし、配布物の実展開・起動を実行する。ネイティブIME／OS倍率／Reader GUI／物理印刷／クリーンWindows／実容量不足／第三者比較は未実行として追跡する。
