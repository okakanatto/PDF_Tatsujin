# 墨消し後に残すTrueTypeヒントの限定条件

2026-10-12。TrueTypeヒンティングの限定範囲を検証します。一般文書に対する安全性は未評価です。既存入力・正解・閾値を維持します。

再構築字体の輪郭を保つだけでは低解像度の描画保持を保証できない。字形内命令と字体全体の初期設定を別に解析し、未評価の実行データを黙って捨てない。

今回の対応条件は、単純字形の空命令、または軸を明示するSVTCA、実輪郭の点番号1個をPUSHB[1]／PUSHW[1]で渡すMDAP[1]、同じ軸のIUPで閉じる命令列に限定する。点番号は各軸で昇順・重複なし、実輪郭内、短い番号はPUSHBへ限定。軸はy、xの順で各1回まで。未使用スタック値、phantom point、制御フロー、関数、CVT、storage、複合字形自身のヒントは拒否する。最大4096命令バイト。全命令の意味と消費を確認できる字形だけ、その命令を保持する。

全体prepは空、または固定の `PUSHW 511; SCANCTRL; PUSHB 4; SCANTYPE` のみ。これは既存固定入力にもあるdropout設定で、任意のデータ領域を許可しない。非空fpgm／cvt／gaspや追加の描画表は未対応として拒否する。再構築maxpのstackと命令長を実保持データから算出し、予約・メーカー情報と未使用集計値を引き継がない。除去字形と対応表を丸ごと保持しない。

固定入力は既存partial-textとshared-fonts-v1を元に、命令を追加した別ディレクトリに事前生成する。単ページ、共有ページ、別名、複製ストリーム、継承、Form、注釈外観、対象外に残る同一字形を含む。除去字形の私的命令データ、非対応命令・不正点番号・未知prepの拒否も含む。期待文字・矩形は既存原本由来、画素正解は入力由来で、製品出力から作らない。

独立検査はPDFium／pypdfの文字、fontToolsの輪郭・命令・maxp、全到達／展開ストリームの元データと私的marker不在を確認する。座標は既存0.5pt、PDFium／Poppler300dpiは既存1px境界の範囲外差0を維持。追加の72／96dpiも同じ入力対出力で範囲外差0。対象外ページは全画素一致。取消・拒否・未保存署名・Undo・保存後再編集を実Qtで確認する。共用字形が残る場合、その字形の存在と削除文字列の不在を区別する。

根拠は[MicrosoftのTrueType命令仕様](https://learn.microsoft.com/en-us/typography/opentype/spec/tt_instructions)、[maxp](https://learn.microsoft.com/en-us/typography/opentype/spec/maxp)。任意のヒンティング、CFF、可変字体、一般CMap、多文字Unicode、DR／DA、一般共有Formの完成を示さない。
