# 小さい作業領域での閲覧と設定

SPEC §4の1024×720論理pxでの検証と、ACCEPTANCE C03の実OS倍率100／150／200%は維持する。本変更は、その基準以下でも操作へ到達できるようにする補足設計であり、実OS試験を合成イベントで代替しない。

## 問題と選択

従来は最小ウィンドウを1024×720に固定していた。画面の利用可能な論理寸法がこれより小さいと、初期配置でサイズを調整しても最小寸法が優先され、下部の操作が画面外に残る。署名・OCR・書き込みには縦スクロールもなく、設定の必要高さが中央文書の高さを押し上げる。

最小寸法を800×480論理pxにし、1024×720と1280×850に加えて800×480、960×540で実アプリのレイアウトを試験する。これは800×480未満の画面への保証ではない。Windowsの倍率、タイトルバー、タスクバーを含む実画面の確認は引き続きC03で行う。

## 操作と実装

- 上部の文書・作業操作、下部のページ・倍率・集中表示・OCR中止は固定する。文書を読む領域と設定を別々にスクロールする。
- 六つの右設定を同じ縦スクロール部品で包む。狭い高さで下部の操作を隠して消すことなく、スクロールとフォーカス移動で到達できる。入力内容・選択中の要素・スクロール位置は通常の更新で作り直さない。
- ステータスと処理説明には省略記号を使い、全文をツールチップとラベルのアクセシブルな文字情報に保持する。説明の長さでOCR中止やページ番号を押し出さない。
- 既存の狭幅でのパネル切替と読書位置の保持を継承する。サイズ変更・パネルのスクロールはPDFやUndoを変更しない。字体、クリック領域、OCRモデル、描画キャッシュを縮小して場所を確保しない。

## 検証

製品のQtウィジェットを使い、各寸法で六つの設定への到達、文書表示、検索、ページ番号、集中表示、署名配置・Undo・保存後の再編集、OCR実行中の閲覧と中止を確認する。設定欄のフォーカスがスクロール領域内へ入ること、操作後に文書と原本が保たれることも検証する。

Qt offscreenのウィジェット画像はレイアウトの証拠として保存する。ネイティブIME、OS倍率、画面表示の体感、Narrator、Acrobatとの比較は別の検証であり、未実行なら未実行と記す。
