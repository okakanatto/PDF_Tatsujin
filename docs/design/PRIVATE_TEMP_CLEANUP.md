# 専用一時フォルダの削除完了

Office変換の固定配布追試で、取消後に増えた一時フォルダが残る失敗を確認した。該当時刻のフォルダは空で、入力ファイルは除去済みだった。元の試験は失敗として保持する。実際に一時的なハンドルを保持したプロセスは未特定である。

Windowsの[削除APIの仕様](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-deletefilew)では、共有モードと開いたハンドルの寿命が削除の完了に関わる。共有削除を許したファイルの250ms保持では元の実装も成功した。ディレクトリ自体を削除共有なしで250ms保持すると、元の実装は空フォルダを残し、所有対象の残留を再現した。フォルダを消せないときに権限を変更したり、他のプロセスを終了したりしない。

PrivateTemporaryDirectoryは通常実行／AppContainerの両方で自身の作成したパスだけを整理する。各試行で根元と配下のリンク／ジャンクションを拒否し、最大1秒の範囲で50msごとに再試行する。既定は1回で終わる。親ディレクトリの実列挙で対象名が消えたことを確認し、最後まで残った場合は削除完了と記録しない。Qtの自動削除と二重管理せず、一つの所有者が削除を管理する。

実ディレクトリハンドルの同じ250ms保持で、修正後は戻る時点で根元も除去された。20回の実Office取消では、元の入力SHA、観測した専用スコープ、戻る時点のフォルダと入力の消失を確認した。一般の一時フォルダ一覧の変化と、自身の処理の残留を区別して記録する。元の即時削除の試験は維持する。

旧版の異常終了で残った所有マーカーのないフォルダを、この修正で自動削除しない。無関係なフォルダ・入力・エンジンの設定は対象外である。永久的なロック・リンク・容量不足やプロセスの強制終了後の包括的な復旧を成功扱いにしない。通常機能、取消、通信権限ゼロと配布後の試験は修正後の実行ファイルへ別途結び付ける。
