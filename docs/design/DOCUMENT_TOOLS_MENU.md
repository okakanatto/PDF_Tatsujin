# 文書ツールの操作導線

作成・変換・既存本文編集・保護・検証を「作成」の一つの長いメニューへ並べる状態では、目的の操作を探しにくく、800×480のコンパクト表示で全項目を同時に確認できない。閲覧の文書領域を狭くする常設の工具一覧は追加せず、上部の文字付き入口を「文書ツール」として目的別のメニューへ分ける。既存SPECの書き込み・署名・注釈・OCR・ページ整理の主要入口は維持する。

目的の区分は「PDFを作成」「書き出し・変換」「本文・ページの編集」「保護・署名」「検証・比較」「フォーム入力データ」「容量・一括処理」。入口から1回で区分、もう1回で既存の実行操作へ到達する。最も長い区分も6項目までとし、追加機能を増やした際に見直す。区分だけの偽機能は作らず、すべて実装済みのQActionへ接続する。

入口のクリック・Space／Enterでメニューを開き、矢印で区分と項目を選び、Escで文書へ戻る。Ctrl+Nは従来どおり画像からのPDF作成、既存の画像出力等のショートカットも維持する。文書未読込・読取専用・OCR中の各項目の有効／無効は従来の状態管理を使い、メニューの移動を理由に編集制限を変えない。

ウィンドウから操作の定義・文書状態を切り離す全面再設計はしない。メニューの構造だけを小さなUI部品へ分け、文書・保存・OCRの実装へ依存させない。既存QActionのobjectNameと実行先を保ち、各機能の実UI試験で到達・取消・保存の回帰を確認する。

実Qtの800×480／1024×720でメニューと最長の区分が画面内に収まり、キーボード選択とEsc復帰が働くこと、各既存機能の実行先と文書制限が維持されることを確認する。Qt offscreenの検証をOS表示倍率・ネイティブGUIや第三者の初見操作の合格へ置き換えない。Acrobatより使いやすいという優越は実比較前に表示しない。
