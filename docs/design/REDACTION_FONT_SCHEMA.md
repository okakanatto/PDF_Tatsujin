# 標準字体の私有データ除去

2026-10-12、dev32の設計。SPEC／TECH／ACCEPTANCEと既存入力・正解・閾値を維持する。一般M5合格やAcrobat同等を宣言しない。

埋込みのないType1字体でも未知の字体属性・参照・ストリームは秘密情報を保持し得る。dev30診断では6条件で私有値が残り、FontDescriptorと外部共有参照の2条件を受理した。独立検査のFAILと旧候補を保護する。ToUnicode・独自Encodingは従来から拒否する。

選択されたType1字体に4つの基本属性以外（古いName、既知のFontDescriptor文字列を含む）があれば整理対象にする。既知属性でも私有値の保持経路になり得るため、属性名だけで安全とは判定しない。既知Helvetica、FontDescriptor／ToUnicode／Widths／FirstChar／LastCharなし、既定／StandardEncoding／WinAnsiEncodingだけの条件では、Type・Subtype・BaseFont・Encodingの名前値から字体を新規作成する。元辞書・参照・私有値をコピーしない。元の字形コードと幅は同じ字体・Encodingで保持できるため、残る文字を別字体へ再符号化しない。dev30の原点保持条件は拡張しない。

元依存関係を記録し、既存の共有資源整理で対象外ページ・Form・複製ストリームに波及させる。最後の参照／復号ストリーム監査で残る回復経路は拒否する。直格納の適格字体も新規作成する。未知の意味を一般に解釈したとは表示せず、独自Unicode・Encoding・descriptor付きや他字体の一般化は保留する。処理は私有builder内で行い、取消・失敗を原本へ反映しない。

最初のfont-schema-v1の2ページ条件は同じPage参照を複製して循環判定された。入力と実行結果は保持し、異なるPage参照のfont-schema-v2を製品変更前に固定した。期待する秘密除去・保持語・描画差0・位置0.5ptは変更していない。v1を製品品質試験として合格扱いしない。

追加の直格納共有4条件でdev31診断の残存を再現した。dev31は梱包せず、dev32で除去する直格納宣言の辞書値を4096件以内で追跡する。共有整理の開始・判定・収束、および全到達辞書の最終監査に値照合を加える。参照番号と復号ストリームの従来の監査は維持する。別ページ・Form・別資源名で同じ宣言値を安全に新規作成し、文書の他属性に元の値が残れば非反映で拒否する。あらゆる意味的に似た辞書を同一と判定する一般化ではない。
