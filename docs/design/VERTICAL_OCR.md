# 日本語の縦書きOCR

右側のOCR設定に「日本語（縦書き）」を追加する。既定の日本語＋英語、横書き日本語、英語の処理と評価条件は維持する。縦書きは既に同梱しているjpn_vertを明示的に選ぶ。横書きモデルと単純に混ぜて自動判別できると表示しない。ルビ・古い字体・見開き・混在する書字方向は追加診断の対象とし、一般的な精度を保証しない。

認識エンジンの書字方向を利用し、縦の文字列を縦方向の位置へ配置する。不可視文字層の論理文字列は上から下、列は右から左を検証する。既存の水平配置で縦長の枠へ押し縮める方式は採用しない。元の可視画像、既存署名・注釈・フォーム、回転・CropBox・UserUnitを維持する。OCR全体を完成候補として確認してから1回のUndoで戻せるように反映し、取消・異常時は部分反映しない。

初回実装前に、既存の変更禁止D11の3ページ目にある3列を新しい補助条件として固定する。元D11や既存manifestを作り直さない。正解は元の生成スクリプトの3文字列とし、空白・改行だけを除いて列順を評価する。CERは2%以下、固定3検索語すべて成功、検索位置は印刷字形の矩形から最大2mm以内、可視画像は全画素一致とする。実UIから縦書き設定、署名追加、OCR、検索・選択コピー、Undo／Redo、保存・再読込を実行し、PDFium・Popplerでも文字列・位置・画素を検査する。取消、モデル不在・不正言語で開始前の状態を保持することも確認する。

既存R01『羅生門』の画像・正解・4検索語は変更せず再診断する。主本文の正解に含まれないルビがあるため、そのCERをM1の横書き閾値と比較しない。改善しなかった点や未実行を残す。バイナリ配布とネイティブ操作の未実行評価は別に追跡する。

Tesseractの[PageIteratorの書字方向API](https://tesseract-ocr.github.io/tessapi/5.x/a02486.html)を参照する。縦書きモデルの選択、実際の読み順・位置・認識精度はこのアプリの試験で判断する。

追加の回転90度・CropBox・UserUnit1.5条件を実行前にfixtures/vertical-ocr-geometry/criteria.jsonへ固定した。保存後の誤認識とPDFiumコピーの逆順を確認したため、成功条件は未達として保持する。現行実装は回転またはUserUnit≠1の縦書き処理をジョブ開始前とワーカー開始時に拒否し、開始前の文書・署名・Undoを保持する。既存の横書きOCRの回転対応は維持する。この処理拒否は元の追加成功条件の合格を意味しない。Popplerによる可視画像比較は実行するが、この環境にpdftotextがないため同エンジンでの文字抽出・位置検査は未実行として記録する。
