# 字体名と宣言を一緒に追跡する

2026-10-12。dev29の同参照別名対応に続き、文字の描画状態が実際に使う字体宣言を資源名と組で記録する。直格納の字体はgetFontIdだけで確認せず、Tf時の宣言も保存する。FontResourceをq／Qで保存・復帰し、Formの子処理へ渡す。文字命令の局所辞書が同名の別宣言を持つ場合は照合して拒否する。参照の字体キャッシュのポインター確認は維持する。

実装前のfont-binding-v1は成功1／拒否3。同じ直格納宣言は保持し、異なる直格納宣言、異なる参照宣言、入れ子の異なる宣言は非反映で拒否する。declが局所辞書で上書きされた場合でも、Tfを省略した元PDFは呼出し元の実際の字体で描画する。元PDF自体が不正という判定ではない。dev29診断は直格納の異なる宣言2件を受理し、位置差6.606pt・範囲外約1.3万画素差を再現した。旧候補PDF・実行記録・FAILを保持する。

同じ宣言の成功対照でも、通常の先頭TJによる移動はPDFium300dpiで29画素差になった。単純な整数幅への置換や原点を移した相対位置の調整は基準を満たさなかった。Glyphの原点が一致しても文字オブジェクトの原点が変わると描画時の浮動小数計算が変わるため、元の文字オブジェクト原点を保持する。固定PDFium7999の公式CPDF_TextObjectの位置計算を参照して解析した。上流コードを取り込まない。

限定範囲はType1のHelvetica、FontDescriptor／ToUnicodeなし、既知の標準またはWinAnsiまたは既定Encoding、単位文字行列、横倍率100%、Tc／Tw=0、元命令の項目が字形だけの場合。先頭が除去される場合は既知の空白字形を1個だけ残して同じ原点を作り、除去範囲全体の移動量と保持字形位置を出力する。除去した字形ごとの幅や個数は出力しない。元の秘密文字命令と文字コードを保持して隠す方式ではない。個別の空白を墨消し対象の内容や成功件数に加算しない。全除去で保持字形がない場合は空白を追加しない。

font-binding-followup-v1の4件は試行前の追試。途中の除去、後続Tj、90度回転、小数原点と17.25ptを含め、保持語・位置0.5pt・PDFium／Poppler300dpi範囲外差分0を維持する。対象の5成功条件は位置差0・両エンジン差分0を確認した。対象26名と独立回帰の確認後、まとまった変更として全体・Windows・配布候補を検証する。完了・未実行は報告で別に記録する。

空白の移動を計算する処理にも取消と出力64MiB上限を適用する。一般の字体・CMap・hint・図形・透明性・出荷評価はこの条件で合格扱いしない。

参照：[PDFium CPDF_TextObject](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/core/fpdfapi/page/cpdf_textobject.cpp)。固定ビルド7999の読み取り原本はevidence/pdfium-7999-cpdf-textobject.cppへ保持する。
