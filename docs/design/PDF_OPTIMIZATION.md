# 容量最適化（M4）

通常保存の再編集性と文字情報を維持し、画像の解像度・画質を下げない方式を検証する。ページ全体の画像化、文字やフォント・OCRの削除、暗号化解除は行わない。既に圧縮・共有されている文書では小さくならないこともある。

## 操作と原本保持

「作成 → PDFの容量を最適化」で開いている文書の現在状態を検査する。候補作成はワーカーで行い、進捗とキャンセルを表示する。完了後に「現在の状態を通常保存した場合」と「最適化した場合」のサイズを比較する。小さくなった候補だけを明示的に文書へ適用でき、1回のUndoで元の状態へ戻る。候補作成だけでファイルを上書きせず、保存は既存の安全な保存経路を使う。取消・失敗・サイズが減らない場合は文書と未保存変更を保持する。

暗号化・証明書署名付き文書は既存の読取専用方針に従う。フォームの入力を先に確定し、候補の適用時には文書revisionを照合する。削除済みの未使用オブジェクトの回収はファイルサイズ整理であり、墨消しや機密情報の除去を保証する機能として案内しない。

## 検証する構成

固定したPDF4QTの未使用オブジェクト除去と参照更新を用いる。ストリームの共有は、同一の辞書と内容を持つ適格なデータだけに限る。ページ、フォーム項目、注釈、しおりなどの辞書は、見た目が同じでも別の編集対象として同一性が必要なため統合しない。構造タグの識別を持つストリーム、外部ファイルを参照するストリームも共有対象から外す。

Flate再圧縮は単独のFlateDecodeだけを対象にし、予測器の前の展開バイト列を完全に保持する。複数フィルターを末尾のFlateだけで処理しない。JPEG・JPX・JBIG2・CCITT等の符号化画像を再符号化しない。空間上限と途中の取消を確認できる限定した展開処理を使い、壊れたデータや上限超過は候補全体を拒否する。vendorの原本は変更しない。

## 実装前に固定する試験

- 重複画像・フォント・内容と、到達不能なデータを持つ自作PDFで、出力サイズが実際に減ることを確認する。文書から到達する展開ストリームは完全一致。
- 本文、ページ数・順序・回転・CropBox・UserUnit、日本語署名・注釈・装飾、フォーム、しおり・リンク、OCR文字を保持する。同一の項目辞書があっても別々に再編集できることを確認。
- 4回転を含む保存PDFを別エンジンで描画し、見た目の画素差0、文字抽出・検索語・宛先・フォーム値・画像展開データの一致を検査する。ストリーム共有で再編集対象が同じオブジェクトへ潰れないことを確認。
- 候補作成→サイズ比較→明示適用→Undo／Redo→通常保存→再読込→再編集の実ウィジェット試験。サイズが減らない時は適用できない。
- 取消、破損Flate、複数フィルター、展開上限、読取専用、失敗後の再試行。原本・未保存状態・既存保存先を保持する。
- M1〜M4回帰と通信権限なしで実行し、未実行のネイティブ試験を合格に変えない。

展開の今回の境界は、入力64MiB／ストリーム、展開128MiB／ストリーム、合計512MiBとする。必要に応じた別モードの対応は追加評価で判断し、上限を超えた文書を成功扱いしない。この境界は拡張機能の技術設計であり、既存のSPEC・ACCEPTANCEの閾値を変更しない。
