# 同じ字体参照の資源別名

2026-10-12。M5の対応字体を複数の資源名で参照する場合も、実際のTf名と描画状態を対応させて再構築する。PDF4QTの字体キャッシュはオブジェクト参照で共有され、字体内部のgetFontIdは最初に使った資源名である。字体の識別と、その命令が使う資源名を区別する。

TextOperationはPDFFontとresourceNameを別々に保持する。Tfで現在名を設定し、q／Qで名前の状態も保存・復帰する。別のContentProcessorで処理するFormには呼出し時の名前を渡し、Form内のTfは子の状態だけを変更する。文字幅、独自CMap、必要な字体除去と再符号化はresourceNameで参照し、字体プログラムの再構築にはPDFFontを使う。参照字体はキャッシュの字体ポインターとも照合する。直格納の標準字体は再生成ポインターを比較せず、その資源名を確認する。既存の未評価ExtGState Fontや未知参照の拒否は維持する。

font-aliases-v1の11件は修正前に固定した。成功9・拒否2。同一ページTj／TJ、q／Q、字体名を別名しか持たないForm、呼出し後の字体復帰、入れ子Form、外観N／R／Dと状態辞書、対象外ページ、別名を最初に使う順序を含む。dev28の診断出力は4件で保持文字が壊れ、3件を拒否、2件が独立検査PASS。要求する成功条件を拒否した3件は機能未達であり、未実行だけにまとめない。修正前の実行・候補PDF・独立FAILと旧exeを保持する。

font-aliases-followup-v1の3件は実装後、試行前に固定した追試。直格納標準字体、Form内でTfを省略して呼出し元字体を使う条件、Identity-Hの別名を確認する。古い固定入力や正解を変更しない。

初期修正の対象試験で、字体を継承するFormは保持文字が壊れた。Formごとに再構築したCID対応は呼出し元の対応と異なり得る。再符号化する文字命令の直前に、その資源名と元のサイズでTfを明示する。名前はPDFDocumentWriterでエスケープし、改行・間隔・行列の状態を維持する。この追試FAILも入力と生出力を保持する。

font-aliases-boundaries-v1の2件は試行前に固定した拒否境界。Tfを省略したFormの局所Font辞書が欠落／空の場合は、資源と描画状態の照合ができないため拒否する。欠落辞書を参照してクラッシュさせない。元PDF自体が不正という判定ではなく、この墨消し実装の対応制限である。

成功条件は保持語、fontTools輪郭一致、文字位置0.5pt以内、PDFium／Poppler300dpiの範囲外差分0、元字体・対応表・選択内容の不在。拒否・取消は原本・未保存変更・Undo・保存先へ反映しない。共有字体の一般性、CFF／可変字体・hint・継承／可変長CMap・DR／DA・一般図形等の残作業をこの修正だけで完了扱いしない。
