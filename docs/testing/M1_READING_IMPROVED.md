# M1：閲覧メモリと初期描画の修正

2026-10-06。最新のローカル試用版は `dist/PDFTatsujin-M1-reading-20261006/PDFTatsujin.exe`。DLL・plugins・assets・licensesを同じ配置で保持する。自作部分はMIT、M2以降には進んでいない。重要な環境未実行が残るため、**M1全体の合格は保留**。

## 実際にできたこと

独自の連続表示に隣接1ページの非同期準備を追加し、表示範囲と前後1ページ以外のコンパイル済みページを解放する。元の256MiB上限や描画品質は維持する。ページ一覧は本文を二度処理せず、1回のコンパイルと既存注釈から縮小画像を作る。OCR・印刷・PDF保存の描画経路は変えていない。[設計と責務](../ARCHITECTURE.md)。

全回帰で初期描画の待ち時間失敗を検出し、単独実行では再現しなかった。調査で、ワーカーの待機開始前に通知が来ると要求が残ったまま眠る経路を見つけた。固定D01で開始を意図的に遅らせる比較を行い、待機前キュー確認なしでFAIL、修正ありでPASSを再現した。元の全回帰失敗との直接の因果は、当時の内部状態を採取していないため推定として区別する。

待機前に未処理要求を確認し、停止通知を同じmutexと同期させた。`cmake/AdaptPdf4QtCompiler.cmake`は固定元ソースのhashを確認してビルド領域にだけ1ファイルを派生する。サブモジュールは改変せず、適用コードも依存lockへ固定した。通常構成は開始遅延なし・修正ONで、検証用DLLのパッケージ化は実際に拒否できた。

## 試験結果

最終製品exeのWindows全自動回帰は **54 PASS／0 FAIL**。追加の単ページ起動、遠い画像ページへの往復・連続ジャンプ、既存の署名・OCR・Undo／Redo・取消・失敗・保存・再編集を含む。既存の入力・正解・検索語・閾値は変更していない。実NTFS拒否後のACL復元、Microsoft Print to PDFドライバも確認した。

縮小画像は回転・CropBox・UserUnit、スキャン、既存注釈・フォームを含む独立描画と画素一致した。新しい往復画像比較は初期fitとページ先頭ジャンプの表示原点差を検出したため、同じ記録済み読書位置へ復元して完全一致を比較するよう試験の設定を修正した。元のFAILと座標差は保持し、画像差の許容値や受入条件を緩めていない。

最終回帰の保存PDFを別エンジンで評価し、日英の固定検索語は各20/20、OCRコピー精度と位置は既定閾値以内、本文の可視内容と既存項目を保持した。最終PDFをFirefoxの専用ヘッドレスプロファイルでも検索・DOM選択・WebDriver PDF印刷できた。GUI操作やOSコピーへ読み替えない。

閲覧測定は[事前設計](../design/READING_PERFORMANCE.md)と同じ入力・手順で実行した。画像PDFのメモリは減ったが、高速移動での描画待ちには残課題がある。Blend2D単一スレッドの比較では中央値とGUI遅延が悪化したため、製品のQPainterは維持した。複数スレッドの比較、物理FPS、Acrobat比較を実行したとは扱わない。
